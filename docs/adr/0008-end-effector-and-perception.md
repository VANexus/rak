# ADR-0008: 末端执行器与感知套件 —— 标准 6 轴 + 吸嘴夹爪 + 末端相机 + 语音

- **状态**: 已接受（形态已定，硬件未成形）
- **日期**: 2026-10-05
- **相关**: ADR-0004（算力分配）· ADR-0005（抓取栈）· ADR-0006（3D 避障）· `src/rak_description` · `docs/architecture.md` §1/§6

---

## 背景

用户 2026-10-05 明确：

- **机械臂尚未成形**，但形态已定：**标准 6 轴机械臂 + 吸嘴（真空吸盘）夹爪 + 末端摄像头**。
- 整机感知：**深度相机 + 平面雷达 + 语音模块**（另有 Jetson 侧 LSM6DSRTR、USB 双目）。
- 当前仓库的 URDF 仍是**旧五轴 demo**（`docs/architecture.md` §1 已标注禁止当作实物模型）。

---

## 决策

### D1. 臂 = 标准 6 轴

6 个旋转关节（J1–J6）的标准构型。URDF/SRDF/MoveIt 配置按此重建，
**替换**现有五轴 demo 与六轴测试夹具。

### D2. 夹爪 = 吸嘴（真空吸盘）→ 抓取范式整体更换

**这是本 ADR 影响最大的一条。** GraspNet / AnyGrasp / GPD 全部是
**平行夹爪的"反极点"（antipodal）抓取** —— **范式不匹配吸嘴**。

吸嘴要的是：**可密封的平坦区域** + 表面法线与接近方向对齐 + 避开孔洞/边缘/高曲率。
对应做法与数据：

| | 平行夹爪（原 ADR-0005） | **吸嘴（本文）** |
|---|---|---|
| 几何判据 | 反极点对 + 力闭合 | **平面拟合 + 法线对齐 + 平坦度 + 距质心距离** |
| 数据集/网络 | GraspNet-1Billion / AnyGrasp | **SuctionNet-1Billion**（同组、同数据集、RA-L 2021；标签为 **seal / wrench / collision**） |
| ROS 实现 | 自定义服务节点 | **PCL `SACSegmentation`（SACMODEL_PLANE + RANSAC）+ 法线估计**，可免训练 |

### D3. 末端摄像头 = eye-in-hand（手眼相机）

装在腕部，近距离精定位。需**手眼标定**（eye-in-hand），并新增一路视频流。

### D4. 感知套件（固定）

| 传感器 | 作用 | 状态 |
|---|---|---|
| 深度相机（Orbbec Astra） | 点云、抓取、3D 避障 | 驱动已有 |
| 平面雷达（WHEELTECH N10P，2D） | SLAM、2D 代价地图 | 驱动已有 |
| **末端摄像头** | 近距精定位、抓取确认 | **新增** |
| 语音模块 | 对话入口 | **新增**（架构文档 E 阶段） |
| LSM6DSRTR（Jetson SPI） | 机体航向（EKF） | overlay 已备 |
| USB 双目 | 视觉 | 驱动已有 |

### D5. 语音归入 `docs/architecture.md` 的 **E 阶段**

先以文字事件验证任务控制，再接 ASR/TTS —— 避免"语音识别问题"与"任务控制问题"混在一起
（`docs/architecture.md` §1 已定此原则）。

---

## 理由

1. **吸嘴的几何判据比反极点简单**：只需找一块够大够平的表面、法线对准，
   **不需要力闭合的两点配对**。对 4 GB 机型是好消息 —— 几何法极轻。
2. **吸嘴在杂乱场景更鲁棒**：SuctionNet 项目口径称吸嘴抓取
   "more reliable and easier to represent"。
3. **可免训练起步**：RANSAC 平面拟合 + 平坦度评分是成熟配方，不依赖模型，
   符合 ADR-0005 "几何优先"的分阶段原则。
4. **末端摄像头是吸嘴的必要补充**：吸嘴需要看到**局部平面质量**，
   腕部近距视角比车体上的深度相机可靠得多。

---

## 后果

### 正面

- 抓取栈的几何阶段**更简单、更轻**，4 GB 上更容易落地。
- SuctionNet-1Billion 与 GraspNet-1Billion **共用数据集与划分**，
  若两者都要评估，数据准备成本可摊薄。
- 标准 6 轴是通用构型，URDF/IK 有大量现成参考。

### 负面（代价，必须承认）

- **吸嘴有原理性抓取盲区**：多孔/网面物体（无法密封）、过重物体（吸力不足）、
  极小或高曲率物体（杯口贴不上）、有孔洞的表面。
  **这些物体在当前方案下抓不了**，不是调参能解决的。
- **末端摄像头挤占 4 GB 预算**：多一路视频流 + 手眼标定。ADR-0004 的天花板更紧。
- **吸嘴需要气路**（真空泵 / 电磁阀）—— 这是**新增的硬件与控制通道**，
  且是**开关量或 PWM**，与 6 个舵机的位置接口不同，必须进协议（见待闭合项 3）。
- **手眼标定是新工作**，且标定误差直接进抓取精度。
- 现有五轴 URDF、`rak_moveit_config` 的 demo 配置、六轴测试夹具**都要重建**。

---

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 沿用 GraspNet / AnyGrasp 做吸嘴抓取 | **范式不匹配**：它们输出的是平行夹爪的夹持位姿，不是吸盘的吸附位姿 |
| 直接上 SuctionNet-1Billion 训练模型 | 与 ADR-0005 "几何优先"冲突；几何法在吸嘴上已足够且免训练，先跑通链路 |
| 用平行夹爪（放弃吸嘴） | 用户已定吸嘴；且吸嘴对平面物体更稳 |
| 末端相机与车体深度相机二选一 | 两者作用不同：车体的看全局与导航，腕部的看局部平面质量与抓取确认 |

---

## 待闭合项

1. **6 轴的几何/限位/DH 参数**未提供 —— 现有 URDF 是五轴占位。
2. **吸嘴规格未知**：口径、真空度、吸力、气路控制方式（继电器开关？PWM 调压？）。
3. **气路控制通道要进协议**：7 个执行器（6 舵机 + 1 吸嘴），
   但吸嘴是**开关/PWM**而非位置 —— 接口类型不同，需在关节级协议里单独定义。
4. **末端摄像头型号/接口/分辨率未知** —— 影响带宽与算力预算（ADR-0004）。
5. **语音模块型号与接口未知**（USB / I2S / 串口？）—— 影响 E 阶段设计。
6. **手眼标定方案未定**（棋盘格？ArUco？）。
7. **ADR-0005 需修订**：其阶段 1/2 的"反极点/几何抓取"与"GraspNet"表述
   对吸嘴不适用，已加交叉引用指向本文。
