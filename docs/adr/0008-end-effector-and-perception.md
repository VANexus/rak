# ADR-0008: 末端执行器与感知套件 —— 标准 6 轴 + 舵机夹爪 + 末端相机 + 语音

- **状态**: 已接受（形态已定，硬件未成形）
- **日期**: 2026-10-05
- **修订记录**: 2026-10-05 初稿误记为**吸嘴（真空吸盘）夹爪**，同日用户更正为
  **舵机夹爪（普通 PWM 舵机）**。因该错误只影响本文与 ADR-0005 的交叉引用、
  且发生在实施之前，**本文直接更正而非新开一篇**；ADR-0005 的相应修订已回退。
- **相关**: ADR-0004（算力）· ADR-0005（抓取栈）· ADR-0009（URDF 建模与标定）· `src/rak_description`

## 背景

用户 2026-10-05 明确：

- **机械臂尚未成形**，形态已定：**标准 6 轴 + 舵机夹爪 + 末端摄像头**。
- 整机感知：**深度相机 + 平面雷达 + 语音模块**（另有 Jetson 侧 LSM6DSRTR、USB 双目）。
- 现有 URDF 是**旧五轴 demo**；另有 `six_axis_sim.urdf.xacro` 六轴**仿真夹具**（尺寸为虚构值）。

---

## 决策

### D1. 臂 = 标准 6 轴

关节链（已有 `six_axis_sim.urdf.xacro` 的结构可直接沿用，只换数值）：

```
base_link
 └ base_yaw_joint        (z 轴)      → shoulder_link
   └ shoulder_pitch_joint (y 轴)     → upper_arm_link
     └ elbow_pitch_joint  (y 轴)     → forearm_link
       └ wrist_yaw_joint  (z 轴)     → wrist_yaw_link
         └ wrist_pitch_joint (y 轴)  → wrist_pitch_link
           └ wrist_roll_joint (x 轴) → tool0  ← 法兰
             └ gripper_joint          → gripper_link
```

`tool0` 是标准法兰坐标，**末端相机与夹爪都挂在它下面**。

### D2. 夹爪 = **舵机夹爪**（普通 PWM 舵机）

- 这是**第 7 个舵机**，与 6 个关节舵机同类（位置控制）。
- **不是吸嘴** —— 因此 [ADR-0005](0005-grasping-stack.md) 的**平行夹爪"反极点"抓取范式重新成立**
  （GraspNet / AnyGrasp / GPD 可用），吸嘴相关的 SuctionNet 方案**作废**。
- URDF 里沿用现有的 **prismatic** 抽象（钳口开合距离），这是 MoveIt 的常规做法。
- ⚠️ **舵机角度 ↔ 钳口开度是非线性的**（连杆机构）。URDF 用 prismatic 抽象即可规划，
  但**硬件接口必须做角度↔开度的映射曲线**，不能当成线性。

### D3. 末端摄像头 = eye-in-hand

装在 `tool0` 上，近距离精定位。需**手眼标定**，方案定为 **chArUco**（见 ADR-0009）。

> ⚠️ **核实结果**：在 `rak` 仓中**没有找到末端相机的任何痕迹**
> （中英文、URDF/xacro/py/yaml/md 全搜过）。现有传感器只有 Astra 深度、USB 双目、N10P 雷达。
> 若该相机曾在上游/姊妹仓出现，本仓需要**新增**：URDF 的 camera link + 驱动 + 标定。

### D4. 感知套件

| 传感器 | 作用 | 状态 |
|---|---|---|
| 深度相机（Orbbec Astra） | 点云、抓取、3D 避障 | 驱动已有 |
| 平面雷达（WHEELTECH N10P，2D） | SLAM、2D 代价地图 | 驱动已有 |
| 末端摄像头 | 近距精定位、抓取确认 | **本仓不存在，需新增** |
| 语音模块 | 对话入口 | **新增**（架构文档 E 阶段） |
| LSM6DSRTR（Jetson SPI） | 机体航向（EKF） | overlay 已备 |
| USB 双目 | 视觉 | 驱动已有 |

### D5. 语音归入 `docs/explanation/architecture.md` 的 **E 阶段**

## 理由

1. **舵机夹爪与 6 个关节同源**：都是 PWM 位置舵机 → **控制通道同构**，
   协议上可以作为"第 7 个位置关节"处理，比吸嘴（开关量/PWM 调压）干净得多。
2. **六轴结构已有现成骨架**：`six_axis_sim.urdf.xacro` 的关节链、轴向、命名都可直接沿用，
   工作量集中在**把虚构数值换成实测参数**（见 ADR-0009）。
3. **反极点抓取范式恢复**：不需要为吸嘴重做一整套抓取栈，ADR-0005 的原方案直接可用。

---

## 后果

### 正面

- 7 个执行器**接口同构**（都是位置），协议设计大幅简化。
- 六轴 URDF 有骨架，改造成本低。
- 抓取栈回到成熟的平行夹爪方案（GraspNet/GPD 生态大）。

### 负面（代价，必须承认）

- **舵机夹爪的夹持力与行程有限**：重物、大尺寸物体抓不了；
  位置舵机**无夹持力反馈**（除非加电流检测），抓取成功与否要靠视觉确认。
- **舵机角度↔钳口开度非线性**：硬件接口要做映射曲线，且**每个夹爪可能要单独标定**。
- **末端相机是本仓的新增项**：URDF link、驱动、标定、带宽与算力（ADR-0004 预算已无余量）
  全都要加。
- 现有五轴 URDF、`rak_moveit_config` 的 demo 配置仍需重建。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 吸嘴（真空吸盘）夹爪 | 用户更正：实际是舵机夹爪。相关 SuctionNet 方案作废 |
| 夹爪用 revolute 建模（转动钳口） | 单舵机 + 连杆的实际运动学更接近**开合距离**；prismatic 是 MoveIt 常规抽象 |
| 用平行夹爪但套用吸嘴的平面吸附算法 | 范式不匹配（见 ADR-0005） |
| 末端相机与车体深度相机二选一 | 作用不同：车体的看全局与导航，腕部的看局部精定位与抓取确认 |
